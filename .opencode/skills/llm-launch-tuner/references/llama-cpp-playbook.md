# llama.cpp: флаги, сигналы в логах, анти-паттерны

**Первый по эффективности шаг — актуальная сборка движка.** На нашем стенде обновление с build 10472
до b11382 (CUDA 12.4) дало **+10…60 %** (CUDA graphs для MTP-драфта #28549, порядок батчей #29019 и др.):
Swift +10…18 %, Qwen3.6 (MoE) +16…60 %, Gemma-26B (MoE) почти вдвое на коротких промптах.
Проверяйте `--help` новой сборки: флаги меняются (в b11382 удалён `--no-mmap` → `--load-mode none`).

Проверяйте справку своей сборки: `llama-server --help`. Ниже — то, что реально влияет на результаты,
и то, что почти никогда не помогает.

## Флаги (по приоритету проверки)

| Флаг | Смысл | Заметки |
| --- | --- | --- |
| `-m` | путь к модели | суффикс `-mtp` = есть голова MTP для спекуляции |
| `-ngl auto\|all\|N` | сколько слоёв на GPU | дефолт `auto` в свежих сборках |
| `--fit on\|off`, `--fit-target MiB`, `--fit-ctx N` | автоподгонка под память | дефолт `on`; следить, чтобы не урезал контекст/слои незаметно |
| `-fa on\|auto\|off` | FlashAttention | **с квантованным V-кэшем обязателен `on`** |
| `-ctk`, `-ctv` | тип KV-кэша (f16/q8_0/q4_0/…, квантованный K+, V+) | q4_0 экономит 1.5–2 ГБ на 80k; q8_0 — компромисс качества |
| `-c` | контекст | реальное значение смотри в логе (`n_ctx_slot`) |
| `-np`, `--parallel` | слоты | один слот = весь контекст одному клиенту |
| `-b`, `-ub` | логический/физический батч | трогать последними; на GPU почти не влияют |
| `-t`, `-tb` | CPU-потоки | то же; не тратить время |
| `--load-mode none\|mmap\|mlock\|mmap+mlock\|dio` | загрузка | `none` ≈ старый `--no-mmap`; mmap ленив, но на NVMe загрузка дольше |
| `--host`, `--port` | сеть | тесты — только `127.0.0.1` |
| `--jinja`, `--chat-template(-file)`, `--chat-template-kwargs` | шаблон чата | встроенный шаблон обычно лучше внешнего; kwargs — недоступные из CLI параметры шаблона |
| `--reasoning on\|off\|auto`, `--reasoning-effort`, `--reasoning-preserve`, `--reasoning-format` | мышление | допустимые значения effort — из шаблона модели, не из справки сервера |
| `--spec-type draft-mtp,draft-simple,ngram-simple,...` | спекуляция | список через запятую; проверьте `--help` своей сборки |
| `--spec-draft-n-max`, `--spec-draft-n-min`, `--spec-draft-p-min`, `--spec-draft-p-split` | параметры драфта | оптимум искать по TG на реальных задачах |
| `--spec-draft-model`, `--spec-draft-ngl` | отдельная draft-модель | для `draft-simple` |
| `--cache-reuse N` | KV-shift переиспользование | для точного префикса не нужен (кэш и так работает) |

## Сигналы в логах (важнее, чем глаза)

| Строка | Что означает |
| --- | --- |
| `slot print_timing: ... prompt eval time = ... tokens per second` | скорость PP по запросу |
| `slot print_timing: ... eval time = ... tokens per second` | скорость генерации (TG) |
| `draft acceptance = 0.xx (N accepted / M generated), mean len = K` | качество спекуляции: доля принятых и средняя длина серии |
| `load_model: initializing, n_slots = …, n_ctx_slot = …` | реальный контекст на слот |
| `quantized V cache requires flash_attn to be enabled` | фатально: включить `-fa on` или взять неквантованный V |
| `common_fit_params: ...` | автоподгонка под память; частые строки = конфиг «в притык» |
| `server did not become healthy` (наш харнесс) | смотреть хвост лога: почти всегда ошибка аргументов/памяти |
| `model loaded` / `listening on http://...` | сервер готов |

## Эмпирика (наши замеры; используйте как ориентир, перепроверяйте на своей машине)

- **MTP**: +50…75 % TG на реальном чате, до 2.4× на простых продолжениях. Без него модель может
  упираться в пропускную способность памяти.
- **`p-min`**: оптимум 0.0–0.5. Высокий `p-min` (0.8+) даёт красивое «принятие», но снижает TG.
- **`n-max`**: 4–5 на реальном чате; 6+ теряет на сложном тексте.
- **`draft-mtp,ngram-simple`**: до ×4–5 на повторяющемся тексте (код, шаблоны), на чате не мешает.
- **KV**: q4_0 → экономия ~1.5–2 ГБ/80k; q8_0 помещается до ~90k на 16 ГБ.
- **Батчи/потоки**: шум; `-ub 2048` только +VRAM.
- **Загрузка**: `--load-mode none` быстрее mmap на быстром NVMe (у нас 3.5 с против 5.5 с).
- **Контекст**: 160k+ при 16 ГБ — обвал TG до ~20 t/s; 131k — практический максимум.
- **Кэш промпта**: повторный запрос с общим префиксом ~6× быстрее (14 с → 2.2 с).
- **Внешние спекуляторы** (наши замеры на 16 ГБ Ada): EAGLE-3 и DSpark в 1.4–3× медленнее MTP;
  DFlash полезен только для копирования/рефакторинга, лучший результат — в связке `draft-dflash,ngram-mod`
  (Qwen3.6: +27…30 % к MTP на коде). Подробности — `docs/research/speculation-research.md`.

## Чеклист «спекуляция не даёт прироста»

1. Модель/файл действительно содержит голову (`-mtp`) и билд знает `--spec-type draft-mtp`?
2. Драфт/модель на GPU, а не на CPU (смотри время TG и размещение в логе при `-lv 4`).
3. Замер на реальной задаче, а не на одном заполнителе.
4. Параметры не в крайностях: попробуйте `n-max 3–5`, `p-min 0.3–0.5`.
5. Контекст не чрезмерный: на длинном контексте большие драфты деградируют.
6. Для ngram-типов нужен повторяющийся контекст — на «свежем» тексте выигрыша не будет.

## Анти-паттерны

- `-fa off` + квантованный V → сервер не стартует.
- `-ub` 2048+ «для скорости» → +VRAM, PP не растёт.
- Гонка за процентом принятия вместо TG.
- Контекст на всю память без запаса → спекуляция и глубина просаживаются.
- Чужой `mmproj`/draft без валидации авторов модели.
- Выводы по одному прогону (разброс ±5 %).
- Оставленный после тестов сервер (держит VRAM и порт).
