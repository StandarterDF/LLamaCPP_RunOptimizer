# RP Model Eval

Скил превращает «протестируй модель на RP» в один воспроизводимый запуск: генерация → судья →
средние баллы. Он не заменяет `bench\rp_quality.py`, а оборачивает его и убирает ручное чтение
харнесса каждый раз.

## Жёсткое правило объёма (экономия)

1. **Скрин — базовый набор (2 сценария, `scenarios_rp.json`): school + seduction.** Гоняется для
   ЛЮБОЙ новой модели, оба режима (`nothink`, `think`), 3 сида.
2. **Полный набор (6 сценариев, `scenarios_rp_full.json`) — только для моделей, которые на скрине
   показали себя лучше всех** (примерно верхняя половина таблицы или явный лидер по нужной оси).
   Не гонять полный набор «на всякий случай»: это 36 генераций + судейство на модель.
3. Скорость (t/s) и «Чисто %» — побочные метрики; они не заменяют оценку судьи.

## Когда использовать

- «Протестируй/оцени модель X на RP», «на что способна модель в роли».
- «Сравни модели по RP», «поставь базовую модель против файнтюна».
- Нужны баллы по 8 осям (ум, память, персонаж, инструкция, инициатива, русский, проза, повторы).

Не для этого скила: чистая скорость/конфиг запуска (это `LLM Launch Tuner`), русский без RP
(`docs\sampling-quality.md`), подбор кандидатов на HF (`gemma4-ru-rp-researcher`).

## Быстрый старт (одна команда)

> **Путь модели — в ОДИНАРНЫХ кавычках.** В PowerShell `${MODELS_DIR}` в двойных кавычках
> раскроется как пустая переменная и путь сломается. Одинарные кавычки не раскрываются.

```powershell
# базовый скрин: 2 сценария × nothink/think, оба судьи
.\.venv\Scripts\python.exe .opencode\skills\rp-model-eval\scripts\run_eval.py `
  --name base_gemma26 `
  --model '${MODELS_DIR}/unsloth/gemma-4-26B-A4B-it-GGUF/gemma-4-26B-A4B-it-UD-IQ3_XXS.gguf' `
  --family gemma --scenarios base --modes nothink,think --judges gemma,qwen
```

Что произойдёт: создаст `bench\quality\suites\suite_rp_eval_<name>_{nothink,think}.json`, поднимет/погасит
`llama-server` на каждый режим (по одному), запишет прогоны в `bench\quality\runs\rp_eval_<name>_<mode>\`,
затем по очереди поднимет обоих судей и посчитает средние баллы (`judge_score.py`).

Полный набор для лидера:

```powershell
... run_eval.py --name base_gemma26_full --model '<тот же gguf>' `
  --family gemma --scenarios full --modes nothink,think --judges gemma,qwen
```

Только судейство по уже готовым прогонам:

```powershell
... run_eval.py --name <name> --model '<gguf>' --skip-generate --judges gemma,qwen
```

## Логи прогона (смотреть ход исследований)

Каждый запуск пишет **единый лог** `logs\rp_eval_<name>_<stamp>.log`: фазы, полный поток вывода
харнесса (по каждой генерации), вывод судей и сводку баллов. Путь печатается в начале и в конце.
Свой путь — флагом `--log <файл>`.

Чтобы следить за прогоном в реальном времени:

```powershell
Get-Content logs\rp_eval_<name>_<stamp>.log -Wait -Tail 40
```

Рядом лежат технические логи: `bench\quality\runs\rp_eval_<name>_<mode>\server.log` (сервер модели)
и `bench\quality\runs\rp_judge_<judge>_<name>\run.log` (сервер судьи).

## Параметры `run_eval.py`

| Флаг | Смысл |
| --- | --- |
| `--name` | короткое имя прогона; попадает в имена suite/каталогов |
| `--model` | путь к GGUF; поддерживает `${MODELS_DIR}` и др. плейсхолдеры |
| `--family` | `gemma` (внешний `gemma4.jinja`, без MTP) · `qwen` (встроенный шаблон + `draft-mtp`) · `other` |
| `--modes` | `nothink,think` (по умолчанию оба) |
| `--scenarios` | `base` (2 сценария, скрин) · `full` (6, только для лидеров) |
| `--seeds` | по умолчанию `11,22,33` |
| `--judges` | `gemma,qwen` · `none` |
| `--draft` | внешний MTP-драфт (`-md`); иначе встроенная MTP-голова модели |
| `--no-spec` | выключить спекуляцию |
| `--ctx`, `--threads` | 51200, 12 по умолчанию (как в RP-конфигах проекта) |
| `--reasoning-budget-think` | бюджет мышления в think (по умолчанию 1024; `-1` — безлимит) |
| `--reuse` | не перегонять режим, если `metrics.jsonl` уже есть |
| `--skip-generate` / `--skip-judge` | пропустить соответствующую фазу |
| `--log` | путь к единому логу прогона (по умолчанию `logs\rp_eval_<name>_<stamp>.log`) |

Сэмплинг фиксирован: **RU-safe temp 0.6 / min-p 0.1 / top-k 0 / top-p 0.95** — чтобы баллы были
сравнимы с уже прогнанными моделями (`docs\models.md`, `docs\rp-quality-eval.md`).

## Судьи и их ограничение

- `gemma` — `gemma-4-26B-A4B-it-UD-IQ3_XXS`, мягче (~4.4), шаблон `gemma4.jinja`.
- `qwen` — `Qwen3.6-35B-A3B-MXFP4_MOE` (20.7 ГБ, влезает за счёт MoE + `--fit on`), строже (~3.3),
  встроенный шаблон, `--spec`.
- **Баллы сравнивать только внутри одного судьи.** 26B мягче, Qwen строже — это разные шкалы.
- **Самооценка.** Если оцениваемая модель — gemma-26B или Qwen3.6, соответствующий судья судит сам
  себя. Пометку об этом обязательно писать в отчёт (и, по договорённости, гонять обоих судей на всех).

## Что читать после прогона

1. **Лог прогона** `logs\rp_eval_<name>_<stamp>.log` — ход всего исследования (фазы, поток харнесса, судьи).
2. Сводку `judge_score.py` (печатает `run_eval.py` в конце и пишет в лог) — средние по 8 осям и по модели.
3. Тексты судьи — `bench\quality\runs\rp_judge_<judge>_<name>\*.txt` (искать конкретные проблемы).
4. Сырые ответы — `bench\quality\runs\rp_eval_<name>_<mode>\raw\`; с thinking — `raw_full\`.
5. Объективные метрики — `bench\quality\runs\rp_eval_<name>_<mode>\summary.md`.

Порядок анализа: сначала заключение судьи (обычный текст), и только при сомнительных местах —
сырой транскрипт. Судья-26B иногда переусердствует и наговаривает.

## Известные грабли (проверено)

- **Think часто сломан**: незакрытый `<channel|>`/` thinking` → пустой ответ. `strip_channels` в
  `bench\rp_quality.py` срезает и gemma-канал, и ` thinking`; но если модель вообще не закрывает канал
  за `n_predict`, ответ теряется. В отчёте честно писать «think непригоден в llama.cpp».
- **Самооценка** (см. выше) — не выдавать за независимый вердикт.
- **Судья-26B пропускает пункты** → N меньше числа ответов; гонять батчами по 3.
- **Спекуляция на RP** у dense/MoE-моделей может не окупаться (см. `gemma4-26a4b-styletune-nothink-nospec`).
  Скорость здесь не цель.
- **Один сервер за раз**: генерация и судья поднимают `llama-server` на GPU. Не запускать параллельно.
- **VRAM судьи**: `rp_judge.py` сам проверяет свободную VRAM (`--min-free-mb`, 12000) и падает,
  если занято. Освободить GPU перед запуском.
- **`.bat` — только CRLF.** Если создаёшь конфиги запуска — нормализовать переводы строк.

## После прогона: обновить документацию (обязательно)

1. `docs\researched.md` — строка в разделе «Качество RP (LLM-судья)»: что проверяли, вердикт, ссылка.
2. `docs\models.md` — строка в «Протестированные» или «Кандидаты»; для базовых/не-RP моделей —
   пометка, что RP мерили.
3. Лог/раздел с числами — `docs\rp-quality-eval.md` (новый подраздел) или отдельный `docs\<модель>.md`.
4. Для новой запущенной модели — `.bat` в `launch\b11382-cu124\` (think и nothink, если умеет оба).
