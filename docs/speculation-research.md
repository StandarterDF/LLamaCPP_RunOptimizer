## 1. Какие бывают методы (и что поддерживает наша сборка)

| Тип | Что это | Нужен отдельный файл? | Комментарий |
| --- | --- | --- | --- |
| `draft-simple` | классическая draft-модель | да (`-md`) | базовый вариант |
| `draft-eagle3` | EAGLE-3: читает скрытые состояния целевой модели | да (`-md`) | выше принятие, чем у простого драфта |
| `draft-dflash` | блок-диффузия: весь блок за один форвард | да (`-md`) | стартовая глубина **15** |
| `draft-dspark` | DFlash + Markov-голова + confidence | да (`-md`) | старт **4–5**; поддержка SpecForge влита 17.08.2026 (PR #26275) |
| `draft-mtp` | MTP-голова модели или assistant-файл | нет (или `-md`) | наш основной рабочий вариант |
| `ngram-cache` | статистика n-грамм | нет | не тестировали |
| `ngram-simple` | поиск последнего совпавшего n-грамма | нет | ×4–5 на повторах |
| `ngram-map-k`, `ngram-map-k4v` | hash-map варианты | нет | для длинных повторов |
| `ngram-mod` | hash-pool, общий для слотов, переменная длина | нет | **лучший «бесплатный» бонус к коду/повторам** |

Типы комбинируются через запятую. Официальные рекомендации: `ngram-mod` —
`--spec-ngram-mod-n-match 24 --spec-ngram-mod-n-min 48 --spec-ngram-mod-n-max 64`;
глубины — MTP 3, DFlash 15, DSpark 4–5; сэмплинг модели не менять ради «принятия».
В нашей сборке НЕТ `--spec-synth-*` (синтетическое принятие) и `--spec-draft-conf-min` (confidence DSpark).

## 4. Факторы, которые взвешены

- **Спекуляция может вредить** на высокоэнтропийных задачах: перевод 9.4 %, креатив 9.6 % принятия —
  в замерах DSpark/D flash для Gemma-4 (williamliao). Нужны per-task проверки и возможность отключить.
- **Глубина не «больше = лучше»**: max 6+ у 26B-A4B-DSpark клампится блоком 7 (1 anchor + 6);
  «лишние» позиции — чистая потеря работы (MoE).
- **У быстрых MoE** оверхед драфта ощутимее: MTP часто выгоднее DSpark (в наших тестах — тоже).
- **EAGLE-3** даёт высокое принятие, но требует ~0.6–2.4 ГБ VRAM; на 16 ГБ надо резать контекст.

## 10. Веб-поиск и проверка свежих приёмов (04.10.2026)

Источники: `docs/speculative.md` и `tools/server/README.md` (llama.cpp), GitHub discussion #25198,
PR #27210 (adaptive MTP), статья «Why MTP doesn't speed up your llama.cpp inference». Наборы —
`bench\suites\tune\*.json`.

### 10.1. `--spec-draft-n-max` + `--spec-draft-p-min` (приём из #25198)

Идея: высокий потолок драфта + высокий `p-min`, чтобы голова «останавливалась, когда не уверена».
Автор получил +15–20 % (на копировании кода до +60 %) на dense Gemma-4-31B / Qwen3.6-27B.

| Модель (наш замер) | Задача | nmax5 pmin(base) | nmax8 pmin0.8 | nmax12 pmin0.8 |
| --- | --- | ---: | ---: | ---: |
| Qwen3.6-35B-A3B (MoE) | рефакторинг | **136.3** | 109.1 | — |
| Gemma-4-31B (dense) | рефакторинг | 42.6 | **45.7** (+7 %) | 42.7 |

**Вывод:** приём **не универсален**. На быстрой MoE (вся в VRAM) он вредит (−20 %), на dense даёт лишь
+7 % (в оригинале был специализированный бенчмарк на копирование кода). Для нас остаётся `nmax5 pmin0.5`.

### 10.2. Температура и «принятие» — скорость не растёт

Один промпт, разная `temperature`, спекуляция включена:

| Модель | temp | TG | Принятие |
| --- | ---: | ---: | ---: |
| Qwen3.6-35B-A3B (RP) | 0.7 / 0.85 / 1.0 | 86.6 / 87.3 / 85.6 | 76 / 69 / 65 % |
| Gemma-4-31B (RP) | 0.6 / 0.8 / 1.0 | 22.9 / 21.5 / 23.0 | 72 / 66 / 64 % |

**Вывод:** снижение температуры повышает принятие драфта, но TG **не меняется** (±3 %, шум). Модель
упирается в чтение весов, а не в число проходов. «Играть температурой» ради скорости бессмысленно.

### 10.3. Прочие флаги сервера — нулевой эффект

На Qwen3.6 (RP + рефакторинг), всё в пределах шума: `-bs/--backend-sampling`, `--poll 100`,
`--spec-draft-p-split 0`, `--swa-full`.

### 10.4. `draft-mtp-adaptive` (PR #27210) — недоступно в b11382

Динамическая глубина драфта (адаптивный n-max). В нашей сборке `--spec-type` его **не содержит**.
Потенциально полезно на структурных/повторяющихся задачах, но требует более свежего билда.

### 10.5. Прочее из документации, что стоит учитывать

- `ngram-mod`: MoE требуют длинных драфтов (`--spec-ngram-mod-n-min 48 --n-max 64`), dense — короче.
- `--cache-reuse N` + prompt caching — для RAG/многотирна с частично совпадающим контекстом.
- `--fit-target MiB` (по умолчанию 1024) — можно уменьшить, чтобы `--fit on` не держал модель у края VRAM.
- `--backend-sampling`, `--swa-full`, `--lookup-cache-*`, `--tools` — в `tools/server/README.md`.

### 10.6. Итог

На 16 ГБ Ada мы у **потолка** для этих моделей: главные рычаги — класс модели (MoE для RP) и MTP вкл/выкл
по задаче; остальное (±3–7 %) — шум. Единственный непроверенный крупный рычаг — свежий билд
с `draft-mtp-adaptive`.
