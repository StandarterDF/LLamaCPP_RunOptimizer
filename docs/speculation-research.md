## 1. Какие бывают методы (и что поддерживает наша сборка)

| Тип | Что это | Нужен отдельный файл? | Комментарий |
| --- | --- | --- | --- |
| `draft-simple` | классическая draft-модель | да (`-md`) | базовый вариант |
| `draft-eagle3` | EAGLE-3: читает скрытые состояния целевой модели | да (`-md`) | выше принятие, чем у простого драфта |
| `draft-dflash` | блок-диффузия: весь блок за один форвард | да (`-md`) | стартовая глубина **15** |
| `draft-dspark` | DFlash + Markov-голова + confidence | да (`-md`) | старт **4–5**; поддержка SpecForge влита 17.08.2026 (PR #26275) |
| `draft-mtp` | MTP-голова модели или assistant-файл | нет (или `-md`) | наш основной рабочий вариант |
| `ngram-cache` | статистика n-грамм | нет | не тестировали |
| `ngram-simple` | поиск последнего совпавшего n-грамма | нет | ×4–5 на повторах |
| `ngram-map-k`, `ngram-map-k4v` | hash-map варианты | нет | для длинных повторов |
| `ngram-mod` | hash-pool, общий для слотов, переменная длина | нет | **лучший «бесплатный» бонус к коду/повторам** |

Типы комбинируются через запятую. Официальные рекомендации: `ngram-mod` —
`--spec-ngram-mod-n-match 24 --spec-ngram-mod-n-min 48 --spec-ngram-mod-n-max 64`;
глубины — MTP 3, DFlash 15, DSpark 4–5; сэмплинг модели не менять ради «принятия».
В нашей сборке НЕТ `--spec-synth-*` (синтетическое принятие) и `--spec-draft-conf-min` (confidence DSpark).

## 2. Локальная проверка на существующих файлах (05.10.2026)

Задача «повторяющегося кода» (рефакторинг функции: вывод копирует большую часть ввода) +

### 2.1. Qwen3.6-35B-A3B (UD-Q2_K_XL, c=131072)

| Тест | Спец-тип | TG short | TG повтор-код | TG regex | Принятие |
| --- | --- | ---: | ---: | ---: | ---: |
| s1 | `draft-mtp` nmax5 pmin0.5 | 92.5 | 104.4 | 87.7 | 72.6 / 77.2 / 62.4 % |
| s2 | `draft-dflash` nmax15 (локальный Q6_K) | 113.4 | 73.5 | 58.4 | 64.6 / 22.9 / 15.7 % |
| **s3** | **`draft-dflash,ngram-mod` nmax6** | 96.0 | **125.6** | **125.3** | 38.3 / 47.9 / 49.0 % |
| s4 | `draft-dflash,ngram-mod` nmax15 | 365.3* | 76.2 | 59.7 | 100 / 22.9 / 15.7 % |

\* s4 на коротком репетитивном промпте — это почти чистая работа ngram (≈100 % принятие).

**Вывод:** для кода/рефакторинга **`draft-dflash,ngram-mod` (nmax6) даёт +20 % на повторяющемся коде и

Для «обычного» чата MTP остаётся лучшим (s5 чуть хуже s1).

## 4. Факторы, которые взвешены

- **Спекуляция может вредить** на высокоэнтропийных задачах: перевод 9.4 %, креатив 9.6 % принятия —
  в замерах DSpark/D flash для Gemma-4 (williamliao). Нужны per-task проверки и возможность отключить.
- **Глубина не «больше = лучше»**: max 6+ у 26B-A4B-DSpark клампится блоком 7 (1 anchor + 6);
  «лишние» позиции — чистая потеря работы (MoE).
- **У быстрых MoE** оверхед драфта ощутимее: MTP часто выгоднее DSpark (в наших тестах — тоже).
- **EAGLE-3** даёт высокое принятие, но требует ~0.6–2.4 ГБ VRAM; на 16 ГБ надо резать контекст.

## 9. Результаты внешних спекуляторов на нашей машине (05.10.2026)

Всё на новой сборке b11382, c=32768, температура 0.6; запросы: `short` (репетитивный),
`chat_repeat` (рефакторинг кода), `chat_code` (regex-функция). TG в t/s.

### 9.1. EAGLE-3 — не окупается на RTX 4060 Ti

| Модель / вариант | short | повтор-код | regex-код | Принятие (short/repeat/code) |
| --- | ---: | ---: | ---: | --- |
| Gemma-4-31B: MTP-assistant (реф.) | 60.3 | 53.0 | 41.4 | 100 / 79 / 69 % |
| Gemma-4-31B: EAGLE-3 Q4_K_M | 24.8 | 23.9 | 17.8 | 92 / 86 / 66 % |
| Gemma-4-31B: EAGLE-3 Q8_0 | 18.2 | 16.9 | 14.8 | 93 / 83 / 74 % |
| Gemma-4-26B-A4B: MTP-assistant (реф.) | 137.8 | 125.0 | 83.9 | 81 / 68 / 42 % |
| Gemma-4-26B-A4B: EAGLE-3 Q4_K_M | 75.2 | 73.3 | 59.7 | 87 / 59 / 50 % |

Принятие у EAGLE-3 **выше**, чем у MTP, но шаг дороже в ~3 раза: драфт читает скрытые состояния
целевой модели и не получает CUDA-graph ускорения. Итог: **в 1.4–2.4 раза медленнее MTP**.
На 16 ГБ Ada EAGLE-3 не рекомендуется; держать как опцию для старших GPU.

### 9.2. DSpark и DFlash — специализированные, не универсальные

Запросы те же: `short` / `повтор-код` / `regex-код`, TG в t/s, сборка b11382, c=32768 (Qwen — 131072).

**Gemma-4-31B** (MTP-референс: 60.3 / 53.0 / 41.4)

| Вариант | short | повтор-код | regex-код | Принятие |
| --- | ---: | ---: | ---: | --- |
| DSpark Q4_K_M, nmax5 | 14.5 | 13.0 | 9.7 | 90 / 74 / 49 % |
| DFlash Q6_K, nmax15 | 50.8 | **75.8** | 27.3 | 56 / 51 / 15 % |
| DFlash Q6_K + ngram-mod, nmax6 | 17.7 | 58.0 | 35.7 | 3 / 48 / 39 % |

**Gemma-4-26B-A4B** (MTP-референс: 137.8 / 125.0 / 83.9)

| Вариант | short | повтор-код | regex-код | Принятие |
| --- | ---: | ---: | ---: | --- |
| DSpark Q8_0, nmax5 | 91.1 | 87.9 | 57.5 | 71 / 60 / 33 % |
| DFlash Q6_K, nmax15 | 103.0 | 109.5 | 54.5 | 31 / 23 / 9 % |
| DFlash Q6_K + ngram-mod, nmax6 | 76.7 | **128.5** | **98.1** | 18 / 49 / 32 % |

**Qwen3.6-35B-A3B** (MTP-референс: 148.0 / 146.1 / 101.5)

| Вариант | short | повтор-код | regex-код | Принятие |
| --- | ---: | ---: | ---: | --- |
| DSpark Q4_K_M, nmax5 | 106.2 | 94.3 | 72.3 | 100 / 79 / 55 % |
| DSpark Q8_0, nmax5 | 118.2 | 106.8 | 82.6 | 100 / 81 / 57 % |
| DSpark Q8_0 + ngram-mod | 96.4 | 107.2 | 82.1 | 42 / 81 / 57 % |
| **DFlash + ngram-mod, nmax6** | 135.5 | **185.8** | **131.7** | 47 / 72 / 46 % |

Выводы:
1. **DSpark на 16 ГБ Ada медленнее MTP на 20–35 %** на всех трёх моделях (при высоком принятии —
   оверхед драфта не окупается). Не использовать.
2. **DFlash — узкоспециализированный инструмент** для задач с копированием/повторами:
   - 31B: **+43 %** на повтор-коде (75.8 против 53.0 при nmax15), но −34 % на генерации нового кода;
   - 26B: в связке с ngram-mod (nmax6) **+17 % на коде** (98.1 против 83.9), повтор-код на уровне MTP,
     но простой промпт −44 %;
   - Qwen (см. ниже) — аналогично: связка с ngram-mod вытягивает код, чистый DFlash слаб.
3. Рекомендация: **MTP — по умолчанию**; отдельный профиль «редактор кода» с `draft-dflash` + `ngram-mod`
   включать только под задачи, где модель много копирует (рефакторинг, патчи, шаблоны).

## 8. Сравнение сборок: build 10472 (старая) vs b11382 (новая, cu124)

Новая сборка скачана в `downloads/llama-b11382-cu124` (0.5.0-dev, CUDA 12.4) по разрешению пользователя.
Замеры на идентичных конфигах (MTP), фоновые процессы и загрузки — числа ±5 %.

| Модель / конфиг | 10472 | b11382 | Прирост |
| --- | ---: | ---: | ---: |
| Swift-1.5, TG чат (3 задачи, сред.) | 37.7 | **41.6** | +10 % |
| Swift-1.5, TG 1.5k | 57.9 | **68.5** | +18 % |

| Gemma-31B, TG повтор-код | 58.9 | 58.3 | −1 % |
| Gemma-31B, TG regex-код | 39.1 | **45.4** | +16 % |

Причина: в upstream после 17.08 попали **CUDA graphs для MTP-драфта (#28549)**, исправление порядка батчей

(Qwen3.6: +16…+60 %), меньший — у dense Gemma-31B (там и так меньше накладных расходов).

**Важно для переноса конфигов:** в b11382 удалён `--no-mmap` — использовать `--load-mode none`.
Остальные флаги наших конфигов совместимы.
